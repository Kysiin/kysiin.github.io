2.2 为什么不存在定义它的正则表达式

正则语言只能用有限状态记忆，无法做无界计数或无界回看，可用泵引理 / Myhill–Nerode 证明。

a. 比 多的串。 需记录 这个可无限大的差值。取 ，泵掉的 段会破坏“ 多于 ”，故非正则。

b. 回文串。 需记住前半段以便与后半段逐字符比较。 中各 两两 Myhill–Nerode 不等价（用 区分），等价类无限，故非正则。

c. 语法正确的 C 程序。 含可任意深度嵌套的 {}、()，本质是 型平衡括号，需要栈而非有限状态，故非正则（它是上下文无关的）。

4.2 把 Program 4.4 写成递归下降（语义动作内嵌）

Program 4.4 是直线式程序语言（straight-line program）的 Yacc 解释器，用全局符号表 table，exp 的语义值就是其求值结果。改写成递归下降需：(i) 消除 + - * / 的左递归并体现优先级；(ii) 把语义动作直接写进解析函数。

文法（消歧后，优先级 高于 ，:=/; 最低）：

prog   → stmlist
stmlist→ stm (';' stm)*
stm    → ID ':=' exp                 { update(&table, id, v); }
       | 'print' '(' explist ')'     { printf("\n"); }
explist→ exp { printf("%d ", v); } (',' exp { printf("%d ", v); })*
exp    → term (('+'|'-') term)*      { 累加/累减 }
term   → factor (('*'|'/') factor)*
factor → INT | ID | '(' exp ')'

递归下降解释器（C 风格伪码，tok 为当前记号，advance() 取下一个）：

Table table = NULL;                 /* 全局符号表 */

void prog(void){ stmlist(); }

void stmlist(void){
    stm();
    while (tok == SEMI){ advance(); stm(); }
}

void stm(void){
    if (tok == ID){
        string id = tok.id; advance();
        expect(ASSIGN);                 /* ':=' */
        int v = exp();
        update(&table, id, v);          /* 语义动作：写符号表 */
    } else if (tok == PRINT){
        advance(); expect(LPAREN);
        explist();
        expect(RPAREN);
        printf("\n");
    } else error();
}

void explist(void){
    printf("%d ", exp());               /* 边解析边打印 */
    while (tok == COMMA){ advance(); printf("%d ", exp()); }
}

int exp(void){                          /* 处理 + - ，左结合 */
    int v = term();
    while (tok == PLUS || tok == MINUS){
        int op = tok.kind; advance();
        int r = term();
        v = (op == PLUS) ? v + r : v - r;
    }
    return v;
}

int term(void){                        /* 处理 * / */
    int v = factor();
    while (tok == TIMES || tok == DIV){
        int op = tok.kind; advance();
        int r = factor();
        v = (op == TIMES) ? v * r : v / r;
    }
    return v;
}

int factor(void){
    if (tok == INT){ int v = tok.num; advance(); return v; }
    if (tok == ID){ int v = lookup(table, tok.id); advance(); return v; }
    if (tok == LPAREN){ advance(); int v = exp(); expect(RPAREN); return v; }
    error(); return 0;
}

要点：把 Yacc 中“归约时执行的语义动作”改为“在对应递归函数返回前执行”。由于递归下降是自顶向下、从左到右，副作用（如 update、printf）的发生顺序与 Yacc 自底向上后序遍历的结果一致，故解释语义不变。用 while 循环实现的左结合即消去了 exp→exp+exp 的左递归。

5.1 改进 Program 5.2 的散列表

Program 5.2 是链地址法散列表：桶数组 + 单链结点 {key,value,next}，用固定大小全局数组。

(a) 平均桶长 > 2 时数组翻倍

把表做成可动态扩容的结构，记录元素个数 nelem 与桶数 size，当 nelem > 2*size 时分配更大数组并 rehash：

struct bucket { string key; void *value; struct bucket *next; };
struct table { struct bucket **buckets; int size; int nelem; };

static unsigned h(string k){ unsigned hv=0; while(*k) hv=hv*65599+*k++; return hv; }

static void grow(struct table *t){
    int nsize = t->size * 2;
    struct bucket **nb = checked_calloc(nsize, sizeof(*nb));
    for (int i=0;i<t->size;i++)
        for (struct bucket *b=t->buckets[i], *nx; b; b=nx){
            nx = b->next;
            int j = h(b->key) % nsize;     /* 按新大小重散列 */
            b->next = nb[j]; nb[j] = b;
        }
    free(t->buckets);                      /* 丢弃旧数组 */
    t->buckets = nb; t->size = nsize;
}

void insert(struct table *t, string key, void *value){
    if (t->nelem > 2*t->size) grow(t);     /* 平均桶长 > 2 */
    int i = h(key) % t->size;
    struct bucket *b = checked_malloc(sizeof(*b));
    b->key=key; b->value=value; b->next=t->buckets[i];
    t->buckets[i]=b; t->nelem++;
}

扩容时旧结点搬到“分配的更大数组”后释放旧数组，整体 摊还。

(b) 允许多张表（把 table 作参数）

如上已把 struct table *t 作为 insert/lookup 的参数，不再用全局 table：

void *lookup(struct table *t, string key){
    for (struct bucket *b=t->buckets[h(key)%t->size]; b; b=b->next)
        if (streq(b->key,key)) return b->value;
    return NULL;
}
struct table *Table_create(int initsize){
    struct table *t = checked_malloc(sizeof(*t));
    t->size=initsize; t->nelem=0;
    t->buckets=checked_calloc(initsize,sizeof(struct bucket*));
    return t;
}

这样同一程序里可同时存在多张独立散列表。

6.3 变量该放寄存器还是内存

int f(int a, int b){
    int c[3], d, e;
    d = a + 1;
    e = g(c, &c);
    return e + c[1] + b;
}
变量 结论 理由
a 寄存器 普通整型形参，未取地址、未逃逸，只在 a+1 用一次。
b 寄存器 普通整型，仅在 return 用；但它跨越对 g 的调用仍存活，应放被调用者保存(callee-save)寄存器（否则需在调用处保存/恢复）。
c 内存（栈帧） 它是数组，需要地址算术访问 c[1]；并且 &c 被取地址、c 传给 g，地址逃逸。
d 寄存器 普通整型；而且 d 赋值后再未被使用（死变量），完全可放寄存器甚至被优化删除。
e 寄存器 普通整型，接收 g 的返回值并在 return 使用，不逃逸。

Program 6.3 的嵌套层次：prettyprint(声明 output) ⊃ show ⊃ indent。第 14 行在 indent 内访问外层 output，跨 2 层。设静态链在帧内偏移为 SL，output 在 prettyprint 帧内偏移为 OUT。

LOAD  r1 ← M[r1 + OUT]        ; r1 = output

display 用一次按层索引取代了逐级链遍历，访问任意外层都是常数 2 条指令。

8.2 应用规整化（canonicalization）重写规则

会用到 Figure 8.1 的恒等式、习题 8.1 的补充规则，以及 CALL 规则：任一 CALL(f,args) 重写为 ESEQ(MOVE(TEMP t, CALL(f,args)), TEMP t)，使每个调用结果立即落入新临时变量，避免嵌套调用相互破坏寄存器。

补充用到的习题 8.1 规则： MOVE(MEM(ESEQ(s,e1)),e2)=SEQ(s,MOVE(MEM(e1),e2))； MOVE(MEM(e1),ESEQ(s,e2)) 在 s,e1 不可交换时 =SEQ(MOVE(TEMP t,e1),SEQ(s,MOVE(MEM(TEMP t),e2)))。

a. MOVE(MEM(ESEQ(SEQ(CJUMP(LT,TEMPi,CONST0,Lout,Lok),LABEL ok), TEMPi)), CONST1)

先用 MEM(ESEQ(s,e))=ESEQ(s,MEM(e)) 把语句提到 MOVE 外，再用 8.1 规则下放赋值，得（线性化）：

CJUMP(LT, TEMPi, CONST0, Lout, Lok)
LABEL ok
MOVE(MEM(TEMPi), CONST1)

即 SEQ(SEQ(CJUMP(...),LABEL ok), MOVE(MEM(TEMPi),CONST1))。

b. MOVE(MEM(MEM(NAMEa)), MEM(CALL(TEMPf,[])))

对右侧 CALL 用 CALL 规则得 MEM(ESEQ(MOVE(TEMP t, CALL(TEMPf,[])), TEMP t)) ESEQ(s, MEM(TEMP t))，其中 s = MOVE(TEMP t, CALL(TEMPf,[]))。由于 s 含函数调用、与左侧地址 MEM(NAMEa) 不可交换，须先把左地址存入临时量：

MOVE(TEMP t1, MEM(NAMEa))          ; 先算并保存目的地址
MOVE(TEMP t,  CALL(TEMPf,[]))      ; 再做调用
MOVE(MEM(TEMP t1), MEM(TEMP t))

c. BINOP(PLUS, CALL(NAMEf,[TEMPx]), CALL(NAMEg,[ESEQ(MOVE(TEMPx,CONST0),TEMPx)]))

两个操作数都是 CALL。先各用 CALL 规则落临时量，并把第二个调用参数里的 ESEQ 提出（MOVE(TEMPx,0) 与 NAMEg 可交换）：

MOVE(TEMP t1, CALL(NAMEf,[TEMPx]))   ; 用“旧的 x”调用 f，结果存 t1
MOVE(TEMPx,   CONST0)                 ; x := 0
MOVE(TEMP t2, CALL(NAMEg,[TEMPx]))   ; 用“x=0”调用 g，结果存 t2
result = BINOP(PLUS, TEMP t1, TEMP t2)

即 ESEQ(MOVE(t1,CALL f),ESEQ(MOVE(x,0),ESEQ(MOVE(t2,CALL g),BINOP(PLUS,t1,t2))))。 关键：CALL 规则保证 f 的结果先存入 t1，从而第二个调用 g 不会破坏它；同时体现了 f(x) 用调用前的 x、g 用置零后的 x 这一求值顺序。

11.1 寄存器分配（3 个寄存器，详细步骤）

3 个寄存器：r1,r2 为调用者保存(caller-save)实参寄存器，r3 为被调用者保存(callee-save)。。

变量活跃区间： c=[1,14] 跨越两次调用；p=[2,7] 跨越 call#1；s=[6,10] 跨越 call#2；t、u 短。c,p,s 在第 6、7 句同时活跃（两两冲突），且各自跨调用 ⇒ 与被破坏的 caller-save r1,r2 都冲突。

冲突图（含预着色 r1,r2,r3，MOVE 边用虚线）：

  • c — p,s,r1,r2,t,u
  • p — c,s,r1,r2
  • s — c,p,r1,r2,t
  • t — s,c, (MOVE r1)
  • u — c, (MOVE r1)
  • r1—r2—r3 互相冲突（不同物理寄存器）
  • MOVE 对：(c,r3) (p,r1) (s,r1) (t,r1) (u,r1)

分配过程：

  1. 合并(coalesce)：受约束（两端本就冲突）而不能合并的有 (p,r1)（4 句 r1←M[p] 时 p 活）、(s,r1)（7 句时 s 活）。可合并的： - (u,r1)：George 准则成立（u 唯一邻居 c 已与 r1 冲突）→ 合并 u→r1。 - (t,r1)：t 的邻居 s,c 都已与 r1 冲突 → 合并 t→r1。 - (c,r3)：George 失败（c 的邻居 p,s 是高度数且不与 r3 冲突），Briggs 也失败（合并后有 4 个高度数邻居 ≥K）→ 暂冻结。

  2. 关键观察：c,p,s 两两冲突，且每个都与 r1,r2 冲突，于是 构成团 只有 3 种颜色，但 r1,r2 已固定占 2 色，c,p,s 三者只能共享剩下的 1 种颜色 r3——彼此却冲突，至多 1 个能进 r3。根本原因：有 3 个跨调用的值，却只有 1 个被调用者保存寄存器 r3。

  3. 因此 simplify / coalesce / freeze 都无法进行（c,p,s 度数均 ≥3），必须 溢出(spill) c,p,s 中的两个。按溢出代价 引用次数度数 选最便宜者：c（仅 2 次引用、且不在循环内）、s（2 次引用）最便宜，p（4 次引用）最贵。 → 溢出 c 与 s，保留 p 进 r3。

  4. 溢出后重写程序（c 在第 1 句存内存、第 14 句前取回；s 在第 6 句存、第 10 句前取回），其活跃区间被切碎，重建冲突图后可着色： - p = r3（跨调用值，放被调用者保存寄存器，最划算）； - t = u = r1（已与 r1 合并）； - c,s 在各自的 def/use 处用临时寄存器（如 r1/r2）短暂承载。

结论： 给定 3 个寄存器（其中仅 1 个 callee-save），此函数必须发生实际溢出——本质是“同时跨调用存活的值（c,p,s）多于可用的被调用者保存寄存器（仅 r3）”。这正是该题想揭示的现象。

13.2 在 Figure 13.1 的堆上运行指针反转（Algorithm 13.6）

堆结构（据书第 274 页图核对）：根/活跃数据是 maketree() 建的二叉搜索树（p 指根 15，r=p.right=37，q=r.key=37 为整型）：

            15  (=p)
           /    \
         12      37  (=r)
                /    \
              20      59
  • 15.left=12, 15.right=37；37.left=20, 37.right=59；12,20,59 是叶子（左右指针为 nil）。
  • 另有两个 list 结点 7、9 互相指（7.link→9, 9.link→7），它们是上一个 let 中 x,y 留下的、已不可达的垃圾循环（标记-清扫能回收、引用计数不能——正是本图要点）。

DFS 从根 p=15 开始，逐字段递归（tree 结点的指针字段按 left、right 顺序），done[x] 记录已处理的字段数。指针反转使“返回指针”临时存进结点字段，用 t 记住前驱。

模拟到“59 第一次被标记”那一刻：

  1. 标记 15；进入 15.left=12（反转 15.left，t=15）。
  2. 标记 12；12 的左右皆 nil，done[12] 走满，回溯：恢复 15.left=12，done[15]=1，t=nil。
  3. 进入 15.right=37（反转 15.right，使其指 t=nil；t=15）。
  4. 标记 37；进入 37.left=20（反转 37.left 指 t=15；t=37）。
  5. 标记 20；左右皆 nil，回溯：恢复 37.left=20，done[37]=1，t=15。
  6. 进入 37.right=59：执行 37.right←t(=15)，t←37，x←59，mark 59，done[59]=0。← 此刻。

此刻的状态：

  • 变量：x = 59，y = 59（刚跟随的指针值），t = 37。
  • 已标记结点：15, 12, 37, 20, 59（5 个活跃结点全部标记；垃圾 7、9 未标记）。
  • 被反转的指针（指回前驱，临时态）：
  • 37.right = 15（37 的右字段暂时指向其前驱链）
  • 15.right = nil（更早反转，指向当时的 t，即 nil）
  • 反转链 59 ←(t)─ 37 ─(37.right)→ 15 ─(15.right)→ nil，编码了 DFS 栈 [15,37]、当前结点 59。
  • 未受影响的指针：15.left=12、37.left=20（均已恢复为正常值），12/20/59 的左右仍为 nil。
  • done 标志：done[15]=1、done[37]=1（左字段已处理、正在处理右字段），done[12]=done[20]=2（已处理完），done[59]=0（刚开始）。

之后 DFS 处理 59 的（空）子节点并回溯，把 37.right、15.right 一一恢复，标记阶段结束——5 个树结点被标记、7/9 作为垃圾留待清扫。
