使用 enum 语法 FSM 设计

typedef enum logic [1:0] {S0,S1,S2,S3} fsm_state;

fsm_state statep;
always@(posedge clk or negedge rstn)begin
    if(~rstn)begin
        statep <= S0;
    end else begin
        case(state)
            S0:if(a) statep<=S1; else statep<=S0; //00 ,若a则01
            S1:if(a) statep<=S2; else if(b) statep<=S0;  //01，若a则10，若b则00
            S2:if(a) statep<=S3; else if(b) statep<=S0;  //10，若a则11，若b则00
            S3:if(a) statep<=S3; else statep<=S3;        //保持11
        endcase
    end
end

assign state = statep;

思考比较enum + case的编程范式和数组查表的编程范式之间的优劣

1. enum+case 写法

优点

  1. 代码可读性高： - 使用 enum 定义状态，代码直观，容易理解和维护。 - case 语句清晰地展示了每个状态的转换逻辑，便于调试和分析。
  2. 调试方便： - 由于状态是枚举类型，仿真和调试时可以直接看到具体的状态名称，而不是抽象的数值。
  3. 不易出错： - 每个状态的转换逻辑都显式地列出，减少了隐含错误的可能性。

缺点

  1. 代码冗长： - 当状态和转换规则较多时，case 语句会显得冗长，增加代码的复杂度。
  2. 状态逻辑修改困难： - 添加或修改状态时需要手动修改 case 语句，容易引入新的错误。

2. 查表法

优点

  1. 代码简洁： - 利用查表的方法，只需要初始化表格和一次状态查表操作，代码简洁明了。
  2. 灵活性高： - 状态转换逻辑存储在外部文件（如 hex 文件）中，修改状态机逻辑时只需修改该文件，不需要修改 Verilog 代码。

缺点

  1. 可读性差： - 状态转换逻辑隐含在查表操作中，代码本身不直观，理解和调试困难。
  2. 硬件实现复杂： - 如果有限状态机很庞大，LUT 的数目会很多，电路会比较复杂
  3. 外部文件依赖： - 需要依赖外部 hex 文件，增加了项目管理和文件同步的复杂度。

start-finish

testbench：

for (i = 0; i < 16; i++) begin
            // 生成随机的乘数和被乘数
            wait (!start);  // 确保上一轮运算已结束
            @(posedge clk);  // 在时钟上升沿触发

            // 随机生成乘数和被乘数
            multiplicand = $random;
            multiplier = $random;
            start = 1;  // 发送start信号

            @(posedge clk);
            start = 0;  // 保证start信号持续一个周期

            // 等待乘法器完成运算
            wait (finish == 1);

            // 检查finish信号，确认可以进行下一次运算
        end

乘数和被乘数生成后发出start信号，multiplier才会接收数据，接着等待一个时钟周期把start信号置零，并等待multiplier发送finish信号，则接受multiplier发送来的结果，并与交予judge检查

32bit 无符号整数除法器

function divide(dividend, divisor)
    if divisor == 0
        error "Divide by zero"
    end if

    quotient = 0
    remainder = 0
    current_bit = 31

    for i = current_bit down to 0
        remainder = (remainder << 1) | (dividend >> current_bit)
        dividend = dividend << 1

        if remainder >= divisor
            remainder = remainder - divisor
            quotient = quotient | (1 << current_bit)
        end if
    end for

    return quotient, remainder
end function
  1. 初始化： - 设定被除数 dividend 和除数 divisor。 - 结果寄存器 quotient 初始化为0。 - 当前位寄存器 current_bit 设置为31（最高位）。 - 余数寄存器 remainder 初始化为0。
  2. 主循环： - 在每次循环中，将 dividend 左移一位并加到 remainder 中。 - 检查 remainder 是否大于等于 divisor。 - 如果 remainder 大于等于 divisor，则从 remainder 中减去 divisor 并将 quotient 的当前位设为1。 - 将 current_bit 减1。 - 重复上述步骤直到所有位都处理完毕。
  3. 结果输出： - 经过主循环，quotient 中存储的就是最终的商，remainder 中存储的就是最终的余数。
