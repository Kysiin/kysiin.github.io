4.2

1. acc是如何获得函数参数的，又是如何返回函数返回值的？

sd      a0,-40(s0)   # 将第一个参数保存到栈帧中的位置 -40(s0)
sd      a1,-48(s0)   # 将第二个参数保存到栈帧中的位置 -48(s0)

2. acc函数中s0寄存器的作用是什么，为什么在函数入口处需要执行sd s0, 40(sp)这条指令，而在这条指令之后的addi s0, sp, 48这条指令的目的是什么？

sd      s0,40(sp)    # 将调用者的 s0 保存到栈中，以便函数结束时恢复
addi    s0,sp,48     # 设置 s0 为当前栈帧的基地址（sp + 48）

在函数入口处保存 s0 寄存器的值，以便在函数返回时恢复。addi s0, sp, 48 设置 s0 为当前栈帧的基地址，方便栈帧内变量的访问。

3. acc函数的栈帧 (stack frame) 的大小是多少？

addi    sp,sp,-48

这条指令将栈指针 sp 向下移动 48 字节，因此栈帧的大小是 48 字节。

4. acc函数栈帧中存储的值有哪些，它们分别存储在哪（相对于sp或s0来说）

  • 调用者的 s0 寄存器：相对于 sp 的偏移量为 40 字节。
  • 第一个参数 (a0)：相对于 s0 的偏移量为 -40 字节。
  • 第二个参数 (a1)：相对于 s0 的偏移量为 -48 字节。
  • 局部变量 sum：相对于 s0 的偏移量为 -32 字节。
  • 循环计数器 i：相对于 s0 的偏移量为 -24 字节。

5. 请简要解释acc函数中的 for 循环是如何在汇编代码中实现的

.L3:

    ld      a5,-24(s0)  # 加载 i 到 a5
    add     a5,a4,a5    # res += i
    sd      a5,-32(s0)  # 存储 sum
    ld      a5,-24(s0)  # 加载 i
    addi    a5,a5,1     # i++
    sd      a5,-24(s0)  # 存储 i

    ld      a5,-48(s0)  # 加载 n
    ble     a4,a5,.L3   # 如果 i <= b，跳转到 .L3

请查阅资料简要描述编译选项-O0和-O2的区别。

-O0（无优化）

  • 目的：该选项禁用大多数优化，主要用于开发和调试阶段。
  • 行为：
  • 生成直接且未优化的代码。
  • 尽可能保持代码结构接近源代码，有助于调试。
  • 编译速度较快，因为编译器不需要进行复杂的优化过程。
  • 生成的二进制文件较大，运行速度较慢

-O2（高级优化）

  • 目的：该选项启用高级别的优化，通常用于生产环境，以提高性能。
  • 行为：
  • 启用各种优化，包括提高执行速度和减小代码大小的优化。
  • 进行常量折叠、循环展开、函数内联和死代码消除等优化。
  • 由于代码结构发生显著变化，可能使调试变得更加困难。
  • 编译时间较长，但生成的可执行文件速度更快，体积更小

请简要讨论src/lab5-1/acc_opt.s与src/lab5-1/acc_plain.s的优劣。

acc_opt.s (优化版本)

优点：

  1. 简洁高效：优化版本的代码行数明显减少，去除了不必要的栈操作和冗余的寄存器存取操作。
  2. 性能提升：减少了内存访问次数，大部分操作在寄存器中完成，提高了执行效率。
  3. 直接跳转：通过简单的条件分支判断 (bgt 和 bne)，直接控制循环流程，避免了多余的内存操作。

缺点：

  1. 可读性：由于代码更加简洁，可能会在某些情况下减少代码的可读性和调试的便利性。
  2. 可维护性：对于复杂的调试过程，优化版本的代码可能不容易跟踪和理解。

acc_plain.s (未优化版本)

优点：

  1. 可读性强：未优化版本保留了完整的栈操作和寄存器存取步骤，代码结构与原始的 C 代码更接近，易于理解和调试。
  2. 调试方便：由于每一步操作都显式表示，使用调试工具时更容易跟踪每个变量的变化和函数的执行流程。

缺点：

  1. 性能较低：包含大量的内存访问和栈操作，增加了运行时间和资源消耗。
  2. 代码冗长：相对于优化版本，代码更为冗长，包含许多不必要的步骤。

4.3

1. 为什么src/lab5-1/factor_plain.s中factor函数的入口处需要执行sd ra, 24(sp)指令，而src/lab5-1/acc_plain.s中的acc函数并没有执行该指令？

在 factor 函数入口处执行 sd ra, 24(sp) 的原因是为了保存返回地址 (ra 寄存器)。这是因为 factor 是一个递归函数，每次递归调用都会覆盖 ra 寄存器中的值，必须将当前的返回地址保存到栈中，以便在递归调用完成后能正确返回到调用点。

在 acc 函数中没有类似的保存返回地址的指令，因为 acc 函数中没有进行递归调用，返回地址在整个函数执行过程中不会被覆盖，所以不需要保存和恢复 ra 寄存器。

2. 请解释在call factor前的mv a0, a5这条汇编指令的目的。

在 call factor 前执行 mv a0, a5 的目的是将递归调用的参数传递给 factor 函数。在 RISC-V 调用约定中，函数参数通过 a0 至 a7 寄存器传递。a5 寄存器中保存了 n - 1 的值，通过 mv a0, a5，将 n - 1 的值传递给递归调用的 factor 函数。

3. 请简要描述调用factor(10)时栈的变化情况；并回答栈最大内存占用是多少，发生在什么时候。

栈变化情况

  • 初始调用

factor(10)：

  • sp 向下移动 32 字节。
  • 保存 ra 和 s0。

  • 参数 n = 10 存储在 sp 的某个偏移位置。

  • 递归调用

factor(9)：

  • sp 向下移动 32 字节。
  • 保存 ra 和 s0。

  • 参数 n = 9 存储在新的 sp 偏移位置。

  • 依次类推，直到调用 factor(0)，此时不会再进行递归调用。

最大内存占用

  • 每次调用占用 32 字节栈空间。
  • factor(10) 需要递归调用 11 次（从 factor(10) 到 factor(0)）。
  • 最大栈占用：32 字节 × 11 = 352 字节。

最大内存占用发生在递归最深的点，即调用 factor(0) 时。

4. 假设栈的大小为 4KB，请问factor(n)的参数n最大是多少？

每次调用 factor(n) 占用 32 字节栈空间。

最大递归深度： 128

请简要描述src/lab5-1/factor_opt.s和src/lab5-1/factor_plain.s的区别

  1. 递归 vs. 循环： - factor_plain.s 使用递归调用，每次调用时将当前状态保存在栈上。 - factor_opt.s 使用循环结构，通过条件跳转和循环迭代来计算阶乘，无需递归调用。
  2. 指令数量和效率： - factor_opt.s 更加简洁，没有保存和恢复寄存器的操作，直接在寄存器中进行计算。 - factor_plain.s 包含更多的指令来处理递归调用和栈操作，代码冗长且执行效率较低。

请从栈内存占用的角度比较src/lab5-1/factor_opt.s和src/lab5-1/factor_plain.s的优劣

  1. factor_plain.s： - 由于递归调用，每次调用都会在栈上分配空间用于保存返回地址 (ra) 和帧指针 (s0) 等信息。 - 每次调用占用 32 字节栈空间。 - 对于 factor(n)，栈的最大深度为 𝑛+1n+1，因此最大栈占用为 32×(𝑛+1)32×(n+1) 字节。
  2. factor_opt.s： - 使用循环结构，无需递归调用，因此不会额外占用栈空间。 - 栈内存占用几乎可以忽略不计，只有初始调用的基本函数开销。

优劣比较

  • factor_opt.s 在栈内存占用方面具有明显的优势，因为它不使用递归调用，大幅减少了栈的使用。
  • factor_plain.s 因为使用递归调用，栈内存占用随递归深度线性增长，在计算较大阶乘时会导致大量的栈空间使用，甚至可能导致栈溢出。

请查阅尾递归优化的相关资料，解释编译器在生成src/lab5-1/factor_opt.s时做了什么优化，该优化的原理，以及什么时候能进行该优化

优化的实现和原理

尾递归优化（Tail Call Optimization, TCO）是一种编译器优化技术，将尾递归函数调用优化为迭代形式，从而避免递归调用带来的栈内存开销。尾递归指的是在一个函数的最后一步是调用自身（或另一个函数），并且该调用的返回值直接作为当前函数的返回值。

编译器在生成 factor_opt.s 时进行了以下优化：

  • 识别尾递归：编译器识别到原始的递归调用是在函数的最后一步，并且没有额外的操作需要在递归调用返回后进行。
  • 转换为迭代：将递归调用转换为循环结构，通过条件跳转和循环控制来代替递归调用。

优化原理

  • 节省栈空间：每次尾递归调用不需要在栈上分配新的帧，直接重用当前栈帧，从而显著减少栈内存占用。
  • 提高效率：减少了函数调用和返回的开销，使得函数执行更高效。

适用条件

尾递归优化可以在以下条件下进行：

  • 递归调用是函数中的最后一个操作。
  • 递归调用的返回值直接作为当前函数的返回值，不需要额外处理。
  • 编译器支持并启用了尾递归优化。

4.4

1. 请简述在src/lab5-1/switch.s中是如何实现 switch 语句的。

在 switch.s 中，switch 语句通过跳转表（jump table）实现，具体步骤如下：

  1. 计算索引：

addi a5,a0,-20

通过 x - 20 计算跳转表的索引 a5。

  1. 检查索引范围：

li a4,6 bgtu a5,a4,.L8

检查 a5 是否在有效范围内（0 到 6）。如果超出范围，跳转到 .L8 处理默认情况。

  1. 跳转表基地址：

lla a4,.L4

获取跳转表基地址 .L4。

  1. 计算跳转地址：

slli a5,a5,2 add a5,a5,a4 lw a5,0(a5) add a5,a5,a4 jr a5

通过索引偏移计算跳转地址，并跳转到对应的代码段。

请简述用跳转表实现 switch 和用 if-else 实现 switch 的优劣，在什么时候应该采用跳转表，在什么时候应该采用 if-else。

跳转表实现 switch 的优点和缺点

优点：

  • 速度快：跳转表实现具有 O(1) 时间复杂度，直接通过索引进行跳转，速度快。
  • 代码简洁：避免了多层次的条件判断，代码较为简洁明了。

缺点：

  • 空间占用：跳转表需要额外的存储空间，尤其当 case 分支稀疏时，会浪费大量空间。
  • 范围限制：适用于 case 值连续或接近连续的情况，对于范围较大的 case 值可能不适用。

if-else 实现 switch 的优点和缺点

优点：

  • 灵活性高：可以处理任意分散的 case 值，灵活性高。
  • 简单实现：无需额外的数据结构，代码简单直接。

缺点：

  • 速度慢：if-else 结构具有 O(n) 时间复杂度，较多分支时性能较差。
  • 代码冗长：多层次的条件判断会使代码冗长且不易维护。

选择跳转表还是 if-else

  • 使用跳转表：
  • 当 case 值连续或接近连续，且分支数量较多时，选择跳转表以提高执行效率。
  • 当对性能要求较高且希望减少判断时间时，使用跳转表。
  • 使用 if-else：
  • 当 case 值分散且不连续，或分支数量较少时，选择 if-else 实现。
  • 当存储空间有限，或实现简单逻辑判断时，使用 if-else。

bubble_sort.s

.text
.globl  bubble_sort

bubble_sort:
    # 保存返回地址
    addi sp, sp, -8
    sd ra, 0(sp)

    # 加载参数
    mv a4, a0  # 将数组地址加载到 a4
    mv a5, a1  # 将长度加载到 a5
    addi a5, a5, -1
    slli a5, a5, 3  # 长度*8

    # 外层循环：循环 (len - 1) 次
    li t0, 0       # 初始化外层循环计数器
outer_loop:
    bge t0, a5, done_outer  # 当计数器 >= len 时退出外层循环

    # 内层循环：比较相邻元素并交换
    li t1, 0       # 初始化内层循环计数器
inner_loop:
    add t2, a4, t1  # 计算 arr[t1] 的地址
    ld t3, 0(t2)   # 将 arr[t1] 加载到 t3

    ld t4, 8(t2)   # 将 arr[t1+1] 加载到 t4

    bge t4, t3, skip_swap  # 如果 arr[t1] <= arr[t1+1]，跳过交换

    # 交换 arr[t1] 和 arr[t1+1]
    sd t4, 0(t2)
    sd t3, 8(t2)

skip_swap:
    addi t1, t1, 8  # 增加内层循环计数器
    blt t1, a5, inner_loop  # 当计数器 < len 时继续内层循环

    addi t0, t0, 8  # 增加外层循环计数器
    j outer_loop   # 继续外层循环

done_outer:
    # 函数尾部
    ld ra, 0(sp)
    addi sp, sp, 8
    ret

fibonacci.s

.text
.globl fibonacci

fibonacci:
    # 保存返回地址和参数n
    addi    sp,sp,-48
    sd  ra,40(sp)
    sd  s0,32(sp)
    sd  s1,24(sp)
    addi    s0,sp,48
    sd  a0,-40(s0)
    ld  a4,-40(s0)

    # 检查n的值
    ld t0, -40(s0)    # 加载参数n
    li t1, 1        # 检查n是否小于等于1
    ble t0, t1, fib_base_case

    # 递归调用fibonacci(n-1)
    ld  a5,-40(s0)
    addi    a5,a5,-1
    mv  a0,a5
    call    fibonacci
    mv  s1,a0
    # 递归调用fibonacci(n-2)
    ld  a5,-40(s0)
    addi    a5,a5,-2
    mv  a0,a5
    call    fibonacci
    mv  a5,a0
    add a0,s1,a5
    j done
fib_base_case:
    # 处理基本情况，返回1
    li a0, 1

done:
    # 恢复栈和返回
    ld  ra,40(sp)
    ld  s0,32(sp)
    ld  s1,24(sp)
    addi    sp,sp,48
    ret
