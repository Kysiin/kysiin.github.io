#### 请查阅资料简要描述编译选项`-O0`和`-O2`的区别。

#### `-O0`（无优化）

- **目的**：该选项禁用大多数优化，主要用于开发和调试阶段。
- 行为：
  - 生成直接且未优化的代码。
  - 尽可能保持代码结构接近源代码，有助于调试。
  - 编译速度较快，因为编译器不需要进行复杂的优化过程。
  - 生成的二进制文件较大，运行速度较慢

#### `-O2`（高级优化）

- **目的**：该选项启用高级别的优化，通常用于生产环境，以提高性能。
- 行为：
  - 启用各种优化，包括提高执行速度和减小代码大小的优化。
  - 进行常量折叠、循环展开、函数内联和死代码消除等优化。
  - 由于代码结构发生显著变化，可能使调试变得更加困难。
  - 编译时间较长，但生成的可执行文件速度更快，体积更小

#### 1. 为什么`src/lab5-1/factor_plain.s`中`factor`函数的入口处需要执行`sd ra, 24(sp)`指令，而`src/lab5-1/acc_plain.s`中的`acc`函数并没有执行该指令？

在 `factor` 函数入口处执行 `sd ra, 24(sp)` 的原因是为了保存返回地址 (`ra` 寄存器)。这是因为 `factor` 是一个递归函数，每次递归调用都会覆盖 `ra` 寄存器中的值，必须将当前的返回地址保存到栈中，以便在递归调用完成后能正确返回到调用点。

在 `acc` 函数中没有类似的保存返回地址的指令，因为 `acc` 函数中没有进行递归调用，返回地址在整个函数执行过程中不会被覆盖，所以不需要保存和恢复 `ra` 寄存器。

#### 2. 请解释在`call factor`前的`mv a0, a5`这条汇编指令的目的。

在 `call factor` 前执行 `mv a0, a5` 的目的是将递归调用的参数传递给 `factor` 函数。在 RISC-V 调用约定中，函数参数通过 `a0` 至 `a7` 寄存器传递。`a5` 寄存器中保存了 `n - 1` 的值，通过 `mv a0, a5`，将 `n - 1` 的值传递给递归调用的 `factor` 函数。

#### 请查阅*尾递归优化*的相关资料，解释编译器在生成`src/lab5-1/factor_opt.s`时做了什么优化，该优化的原理，以及什么时候能进行该优化

#### 优化的实现和原理

尾递归优化（Tail Call Optimization, TCO）是一种编译器优化技术，将尾递归函数调用优化为迭代形式，从而避免递归调用带来的栈内存开销。尾递归指的是在一个函数的最后一步是调用自身（或另一个函数），并且该调用的返回值直接作为当前函数的返回值。

编译器在生成 `factor_opt.s` 时进行了以下优化：

- **识别尾递归**：编译器识别到原始的递归调用是在函数的最后一步，并且没有额外的操作需要在递归调用返回后进行。
- **转换为迭代**：将递归调用转换为循环结构，通过条件跳转和循环控制来代替递归调用。

#### 优化原理

- **节省栈空间**：每次尾递归调用不需要在栈上分配新的帧，直接重用当前栈帧，从而显著减少栈内存占用。
- **提高效率**：减少了函数调用和返回的开销，使得函数执行更高效。

#### 适用条件

尾递归优化可以在以下条件下进行：

- 递归调用是函数中的最后一个操作。
- 递归调用的返回值直接作为当前函数的返回值，不需要额外处理。
- 编译器支持并启用了尾递归优化。

#### 1. 请简述在`src/lab5-1/switch.s`中是如何实现 switch 语句的。

在 `switch.s` 中，`switch` 语句通过跳转表（jump table）实现，具体步骤如下：

1. **计算索引**：

   ```
   addi    a5,a0,-20
   ```

   通过 `x - 20` 计算跳转表的索引 `a5`。

2. **检查索引范围**：

   ```
   li      a4,6
   bgtu    a5,a4,.L8
   ```

   检查 `a5` 是否在有效范围内（0 到 6）。如果超出范围，跳转到 `.L8` 处理默认情况。

3. **跳转表基地址**：

   ```
   lla     a4,.L4
   ```

   获取跳转表基地址 `.L4`。

4. **计算跳转地址**：

   ```
   slli    a5,a5,2
   add     a5,a5,a4
   lw      a5,0(a5)
   add     a5,a5,a4
   jr      a5
   ```

   通过索引偏移计算跳转地址，并跳转到对应的代码段。

#### 请简述用跳转表实现 switch 和用 if-else 实现 switch 的优劣，在什么时候应该采用跳转表，在什么时候应该采用 if-else。

#### 跳转表实现 `switch` 的优点和缺点

**优点**：

- **速度快**：跳转表实现具有 O(1) 时间复杂度，直接通过索引进行跳转，速度快。
- **代码简洁**：避免了多层次的条件判断，代码较为简洁明了。

**缺点**：

- **空间占用**：跳转表需要额外的存储空间，尤其当 `case` 分支稀疏时，会浪费大量空间。
- **范围限制**：适用于 `case` 值连续或接近连续的情况，对于范围较大的 `case` 值可能不适用。

#### if-else 实现 `switch` 的优点和缺点

**优点**：

- **灵活性高**：可以处理任意分散的 `case` 值，灵活性高。
- **简单实现**：无需额外的数据结构，代码简单直接。

**缺点**：

- **速度慢**：if-else 结构具有 O(n) 时间复杂度，较多分支时性能较差。
- **代码冗长**：多层次的条件判断会使代码冗长且不易维护。

### 选择跳转表还是 if-else

- **使用跳转表**：
  - 当 `case` 值连续或接近连续，且分支数量较多时，选择跳转表以提高执行效率。
  - 当对性能要求较高且希望减少判断时间时，使用跳转表。
- **使用 if-else**：
  - 当 `case` 值分散且不连续，或分支数量较少时，选择 if-else 实现。
  - 当存储空间有限，或实现简单逻辑判断时，使用 if-else。

### bubble_sort.s

```
.text
.globl  bubble_sort

bubble_sort:
    # 保存返回地址
    addi sp, sp, -8
    sd ra, 0(sp)

    # 加载参数
    mv a4, a0  # 将数组地址加载到 a4
    mv a5, a1  # 将长度加载到 a5
    addi a5, a5, -1
    slli a5, a5, 3  # 长度*8

    # 外层循环：循环 (len - 1) 次
    li t0, 0       # 初始化外层循环计数器
outer_loop:
    bge t0, a5, done_outer  # 当计数器 >= len 时退出外层循环

    # 内层循环：比较相邻元素并交换
    li t1, 0       # 初始化内层循环计数器
inner_loop:
    add t2, a4, t1  # 计算 arr[t1] 的地址
    ld t3, 0(t2)   # 将 arr[t1] 加载到 t3

    ld t4, 8(t2)   # 将 arr[t1+1] 加载到 t4

    bge t4, t3, skip_swap  # 如果 arr[t1] <= arr[t1+1]，跳过交换

    # 交换 arr[t1] 和 arr[t1+1]
    sd t4, 0(t2)
    sd t3, 8(t2)

skip_swap:
    addi t1, t1, 8  # 增加内层循环计数器
    blt t1, a5, inner_loop  # 当计数器 < len 时继续内层循环

    addi t0, t0, 8  # 增加外层循环计数器
    j outer_loop   # 继续外层循环

done_outer:
    # 函数尾部
    ld ra, 0(sp)
    addi sp, sp, 8
    ret
```
