# 第九部分　运动捕获、角色绑定与表情动画

## 8.1 基于运动捕获的关节动画：原理与优缺点

**原理**：让真人演员表演，用传感设备记录其身体各部位在空间中的运动（位置/朝向），再把数据映射到数字角色的骨架上，驱动关节动画。常见技术：

| 技术 | 方式 | 特点 |
|---|---|---|
| 光学式（被动标记） | 多台红外相机跟踪反光标记点 | 精度高、可多人、需标记与专用场地、易遮挡 |
| 光学式（主动/无标记） | 主动发光标记或基于视觉的姿态估计 | 无需穿戴、受光照/遮挡影响 |
| 惯性式（IMU） | 穿戴陀螺/加速度计 | 便携、不受遮挡、易漂移 |
| 机械/电磁式 | 外骨骼、电磁场 | 早期方案，受干扰/活动受限 |

**优点**：

1. **真实、细腻**：保留真人的微动作、重量感、节奏与个性，是"最难伪造"的部分；
2. **效率高**：几分钟的表演即可得到高质量动画，远快于手工关键帧；
3. **数据量大、可复用**：一次采集可反复使用、可建立动作库（配合运动图/运动匹配）；
4. **表演可控**：导演可直接指导演员，情绪与表演更准确；
5. **复杂动作可行**：跑跳、打斗、舞蹈等难以手工制作的动作。

**缺点**：

1. **设备与场地昂贵**，需要专业团队与校准；
2. **遮挡/丢失/噪声**：标记被遮挡、磁干扰、IMU 漂移，需要大量**清理与修补**（补洞、平滑、去抖）；
3. **重定向困难**：源演员与目标角色骨架比例不同，需重定向并处理脚滑/穿地/自碰撞；
4. **受演员能力限制**：无法表演非人类动作（飞龙、四足怪兽、超人体能）；
5. **风格受限**：动画风格必须"像真人"，卡通化夸张需二次加工；
6. **不易编辑**：改一个动作往往要重捕或做复杂的运动编辑/拼接；
7. **数据管理与版权**：数据量大、涉及演员授权。

>**对比记忆**：动捕 = "真实但受限、贵、需清理"；手工关键帧 = "自由但费时、难真实"；程序化/物理 = "自动但难控制"。

## 8.2 骨架与角色模型的绑定原理

**绑定（binding / rigging）**：建立**骨架**与**网格模型**之间的驱动关系，使骨骼运动时网格随之变形。

**基本概念**：

- **绑定姿态（bind pose / rest pose）**：建模时的初始姿态，此时网格与骨骼对齐；
- **骨骼的变换**：每根骨骼 i 有绑定时的世界变换 M_i^{bind}（含平移+旋转），动画时为 M_i^{cur}；
- **权重（skin weights）**：每个网格顶点 v 受哪些骨骼影响、影响多少，权重 w_{i}(v) ≥ 0 且 Σ_i w_i = 1（通常每顶点最多 4 根骨骼）。

**顶点的蒙皮变换**（把顶点从绑定姿态变到当前姿态）：

$$
\mathbf{v}' = \sum_{i} w_{i}\,\left(M_{i}^{cur}\,\left(M_{i}^{bind}\right)^{-1}\right)\mathbf{v},
\qquad \sum_i w_i = 1
$$

其中 M_i^{cur}(M_i^{bind})⁻¹ 是骨骼 i 的"**相对变换**"（从绑定姿态到当前姿态的位移），称为**蒙皮矩阵**。直观理解：每个顶点被若干骨骼"拉扯"，最终位置是各骨骼变换结果的**加权平均**。

**权重的来源**：手工绘制（刷权重）、**自动权重**（热扩散/测地距离/最近骨骼/包络）、基于机器学习的自动蒙皮。

**绑定的关键问题**：

- 关节处需要**平滑过渡**（权重渐变），否则出现折痕/断裂；
- 权重过大范围会"带动"不该动的部分（如手臂带动胸部）；
- 旋转大的关节会出现 **candy-wrapper（糖纸）效应**与**体积塌陷**——线性混合把旋转矩阵加权平均，不再是旋转，导致收缩；
- 改进：**双四元数蒙皮（DQS）**（对四元数插值、保持体积）、辅助骨骼/校正骨骼、校正 blendshape、肌肉系统。

>**考点**：写出顶点混合公式（含 M^{cur}M^{bind,−1} 与 Σw=1）；说明权重的意义；指出线性混合的缺陷（candy-wrapper / 体积损失）与 DQS 改进。

## 8.3 运动重定向（Motion Retargeting）的基本原理

**定义**：把源骨架（演员）的运动数据映射到**不同比例、不同结构**的目标骨架（角色）上，同时保持运动的**语义**（走、跳、挥手）与**物理约束**（脚接触地面、不穿地）。

**基本流程**：

1. **建立骨骼对应**（mapping）：源骨架的每根骨对应目标骨架的哪根骨（通常手工指定 + 自动匹配）；
2. **角度重定向**：把源骨骼的局部旋转赋给对应目标骨骼（可做缩放/偏移校正）；
3. **根节点处理**：把根位移按**身高/腿长比例缩放**，保持速度与步幅合理；
4. **末端修正（IK）**：用 IK 把目标角色的脚/手拉到期望的接触位置，消除脚滑与穿地；
5. **后处理**：平滑、去抖、限制关节角、修正自碰撞、重心平衡。

**带几何模型的运动重定向存在哪些挑战**（大纲明确考点）：

| 挑战 | 说明 |
|---|---|
| **比例差异** | 目标角色腿短/臂长不同，直接复制角度会导致脚悬空/穿地、手够不到，需要 IK 修正与根节点缩放 |
| **脚部接触与滑动** | 必须检测"支撑相（stance）"并锁定脚的位置，否则出现"滑步/溜冰"；接触点还要与地面高度匹配 |
| **自碰撞** | 体型变化后手臂可能插进身体、大腿相互穿插，需要碰撞检测与避让（改姿态） |
| **环境碰撞** | 与场景物体、道具的交互（坐下、开门、搬运）需要保持接触与合理姿态 |
| **重心与平衡** | 目标角色的质量分布不同，姿势可能"站不住"，需保持质心在支撑多边形内 |
| **关节限位与自由度差异** | 目标骨架的关节范围/自由度可能更少，源动作可能不可达 |
| **风格与自然性** | 不同体型应有不同节奏与幅度（矮个步伐快、胖人摆动大），纯几何映射会"僵硬/失真" |
| **网格细节** | 蒙皮权重不同，同一关节角在不同模型上产生的形变质量不同（塌陷、褶皱） |

>答题结构：**角度映射 + 比例缩放 → 末端 IK 修正 → 接触/碰撞/平衡约束 → 平滑与风格保持**，并逐条说明挑战。

## 8.4 运动图（Motion Graph）的基本原理

**定义**：把一段或多段运动捕获数据组织成**有向图**：**节点**是运动片段（一帧或若干帧的短片段），**边**表示两个片段之间可以**无缝拼接**的转移关系。

**构造步骤**：

1. **切分**：把长动作（走、跑、转身、跳跃）切成短片段/帧；
2. **相似度计算**：对任意两帧（通常是一段的末帧与另一段的首帧）计算距离，考虑关节位置、速度、朝向、根节点位移等，加权求和：
$$
d(f_a,f_b) = \sum_{k} \omega_k\left\| \mathbf{p}_k^{a}-\mathbf{p}_k^{b}\right\|^{2} + \cdots
$$
3. **建边**：若距离小于阈值（且过渡在时间上可行），则在两个节点间加边，边权 = 片段长度 + 转移代价（距离）；
4. **可选节点**：加入原地待机（idle）、起步/停止等"万能"节点，保证图连通。

**使用（查询与合成）**：

- 用户给出目标（走到某位置、沿路径、某风格），在图上做**图搜索**（Dijkstra/A*），代价包含"到目标的距离"与"转移代价"；
- 沿最优路径播放片段，在转移处做**短混合（blend）**，得到连续的新运动；
- 可加入约束（避开障碍、保持速度）。

**优点**：自动生成大量新运动、保留真实细节、片段间过渡无缝、数据可复用、实现清晰。
**缺点**：**依赖数据库覆盖**（库里没有的动作生成不出来）；构图与相似度阈值需调；转移处仍可能不自然（脚滑/抖动）；图规模大时搜索慢；难以精确满足末端约束。

## 8.5 运动匹配（Motion Matching）的基本概念

**思想**：不显式构图，而是**每一帧都在大型动作数据库中搜索"最匹配当前状态与未来意图"的帧**，直接切换（带短混合）到该帧继续播放。

**关键要素**：

1. **特征向量**：描述"当前状态 + 期望未来"——当前姿态（各关节位置/速度）、根节点速度、**未来轨迹**（未来 0.5~1 秒的期望位置/朝向）、用户输入（摇杆方向）；
2. **数据库**：大量动捕帧，每帧预计算特征，建 **kd-tree / ANN** 索引；
3. **匹配**：在数据库中找特征距离最小、且"当前帧之后仍能继续播放"（避免刚播过又跳回，用冷却/惩罚）的帧；
4. **过渡**：切换到匹配帧时做短时间混合（inertialization/交叉淡入）避免跳变；
5. **循环**：每帧或每隔几帧重复搜索。

**与运动图的区别**：

| | 运动图 | 运动匹配 |
|---|---|---|
| 结构 | 显式图（节点+转移边） | 无图，直接对数据库做最近邻搜索 |
| 转移 | 预计算、离散 | 运行时逐帧搜索、连续 |
| 手工工作 | 需切分与阈值调参 | 主要是特征设计与权重 |
| 灵活性 | 受图结构限制 | 易加数据、响应控制更灵活 |

**优点**：质量高、动作自然、数据驱动、实现相对简单（无需构图）、易于扩展数据与响应玩家输入（游戏工业主流）。
**缺点**：需要**大数据库**与内存；每帧搜索有开销（需加速结构）；特征权重难调；可能抖动/跳变（需冷却与混合）；同样无法生成库外动作。

## 8.6 基于 Blend Shapes 的表情动画原理

**Blend Shapes（混合形状 / morph targets）**：预定义一组"表情基形状"（如微笑、皱眉、张嘴、眨眼），运行时用**权重**把它们线性叠加到中性脸上。

**数学表示**：

$$
\mathbf{V}(w) = \mathbf{V}_{0} + \sum_{i=1}^{m} w_{i}\left(\mathbf{V}_{i}-\mathbf{V}_{0}\right),
\qquad w_i\in[0,1]\ (\text{或允许}>1\text{ 做夸张})
$$

其中 V₀ 为中性表情，V_i 为第 i 个表情目标，ΔV_i = V_i − V₀ 为**位移场（delta）**。渲染时还需混合法线/切线/纹理（否则光照不匹配）。

**表情动画的制作与驱动**：

1. 建模师按**FACS 的动作单元（AU）**或常用表情制作 blendshape（左右对称可拆开）；
2. 权重由动画师设关键帧，或由**面部动捕**（标记点/头戴相机/视频）自动求解；
3. 可再叠加程序化细节（眨眼、呼吸、微抖动）。

**优点**：实时、简单、可控、可组合、工业标准（游戏/影视），权重有明确语义（"微笑 0.6"）。
**缺点**：需要大量手工建模（每个表情一个目标）；**线性叠加会失真**（多个表情同时激活时形状不自然，需校正形状/组合修正）；难以表现皮肤的滑动、皱纹细节、体积变化；高模上存储开销大（每目标一套顶点）。

## 8.7 FACE IK 的原理与 FACS

**FACS（Facial Action Coding System）**：Ekman 与 Friesen 提出的面部动作编码系统，把面部肌肉运动分解为若干**动作单元（Action Units, AU）**，例如：

| AU | 名称 | 表现 |
|---|---|---|
| AU1 | 内眉上抬 | 眉毛内侧上提（悲伤/担忧） |
| AU4 | 皱眉 | 眉间下压（愤怒/专注） |
| AU6 | 颧骨上提 | 眼周收紧、"鱼尾纹"（真笑） |
| AU12 | 嘴角上扬 | 微笑 |
| AU20 | 嘴唇拉伸 | 恐惧/紧张 |
| AU26 | 下颌下降 | 张嘴 |

FACS 给出"肌肉运动 → 表情"的**可组合词典**，是表情捕捉与 blendshape 设计的通用语言。

**FACE IK（面部逆向运动学）**：

- **问题**：给定面部若干**特征点/标记的目标位置**（如嘴角、眼角、眉心的目标位置），求各 blendshape 的权重（或面部骨骼角度）；
- **形式**：与关节 IK 同构——
$$
\min_{\mathbf{w}}\ \left\|\mathbf{P}(\mathbf{w})-\mathbf{P}_{target}\right\|^{2} + \lambda\left\|\mathbf{w}-\mathbf{w}_{0}\right\|^{2}
\quad \text{s.t. } 0\le w_i\le 1
$$
其中 P(w) 是由 blendshape 线性组合决定的特征点位置（通常对 w 是线性的，可化为最小二乘/二次规划，求解很快）；
- **用途**：把面部动捕的少量标记点（甚至 2D 视频关键点）转换成可动画的 blendshape 权重；也用于"给几个点，自动摆出表情"的交互工具；
- **难点**：权重耦合（多个 AU 影响同一区域）、需要正则化保持自然、限位、时序平滑、个体差异（同一表情在不同人脸上的形状不同）。

>**对比**：Blend Shapes 是"**正向**"（给权重得到形状），FACE IK 是"**反向**"（给形状/标记点求权重），二者常配合使用（动捕 → FACE IK 解权重 → blendshape 驱动模型）。
