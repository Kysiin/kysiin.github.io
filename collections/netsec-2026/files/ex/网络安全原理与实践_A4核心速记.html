网络安全原理与实践 A4 核心速记

下载 PDF离线 / 打印版

适用范围：基于 Network_Basics、MAC_ARP、Sniffing_Spoofing、TCP_Attacks、Firewall、VPN、DNS、PKI、BGP 习题压缩。

1. 基础

  • 传输层地址=端口，网络层地址=IP，链路层地址=MAC。
  • 服务器 bind() 是为了固定本地接收端点；客户端通常不手工 bind()，内核自动分配临时端口。
  • 0.0.0.0 表示监听所有本地接口；只收本机流量用 127.0.0.1。
  • 源 IP 由路由决定，源端口通常由内核从临时端口池分配。
  • TCP 是字节流，无消息边界；UDP 保留报文边界。

2. 抓包与 ARP

  • 混杂模式：让网卡接收非本机目的帧；交换网络下仍不保证能看到别人之间的单播。
  • 抓包需要特权；Wireshark 常由特权子进程 dumpcap 真正抓包。
  • ARP 作用：同一二层网络内把 IP 解析成 MAC。
  • 访问同网段主机：ARP 目标是对方 IP；访问外网：ARP 目标是默认网关 IP。
  • ARP 请求二层目的 MAC=ff:ff:ff:ff:ff:ff，ARP 目标 MAC 通常未知填 0。
  • ARP 无认证，可被伪造请求、伪造响应、gratuitous ARP 投毒。
  • ARP 投毒通常只能在同一广播域内做，不能跨路由器远程直接做。
  • MITM：同时毒化 A 和 B，让双方都把对方 IP 映射到攻击者 MAC。
  • 只投毒不转发=DoS；开 IP forwarding=可透明转发；要改包通常需自己重发并重算校验和。

3. 字节序与过滤

  • 网络字节序=大端；主机字节序可能小端。
  • 协议字段入包前做 hton*，出包解析时做 ntoh*。
  • 内核态过滤比用户态过滤高效：先过滤再复制，减少开销。
  • pcap_open_live(..., promisc=0, ...) 常只能看到本机相关流量。

4. TCP

  • connect() 触发三次握手。
  • listen() 进入监听状态，不等连接才返回。
  • accept() 取出一个已建立连接，并返回新的已连接 socket。
  • SYN Flood 目标是耗尽半开连接队列/状态，不一定让整机死机。
  • SYN Flood 常伪造随机源 IP：避免本机或真实主机回 RST，增加半开连接保留时间。
  • 若伪造源 IP 对应真实在线主机，该主机通常会对意外 SYN+ACK 回 RST。
  • RST 攻击需要知道连接四元组和可接受序列号。
  • SSH 仍可能被 TCP RST 断开，但难以被有效会话劫持。
  • 会话劫持要对齐源/目的 IP、端口、SEQ、ACK；Telnet 易中招，SSH 因加密完整性保护难中招。
  • 若注入序列号超前太多，接收方会认为有缺口，攻击通常失败。
  • TCP 不适合经典反射放大：三次握手让源地址伪造难以完成。
  • Mitnick 攻击要点：信任关系、可预测 ISN、源地址欺骗、被冒充主机最好离线。

5. Netfilter / 防火墙

  • 五个 hook：PRE_ROUTING、LOCAL_IN、FORWARD、LOCAL_OUT、POST_ROUTING。
  • 入站到本机：PRE_ROUTING -> LOCAL_IN。
  • 经路由器转发：PRE_ROUTING -> FORWARD -> POST_ROUTING。
  • 本机发出：LOCAL_OUT -> POST_ROUTING。
  • NF_ACCEPT=继续后续处理，不是“立刻最终放行”。
  • NF_DROP=终止该包后续处理。
  • filter/INPUT -> LOCAL_IN，nat/OUTPUT -> LOCAL_OUT，mangle/POSTROUTING -> POST_ROUTING。
  • Stateful firewall 依赖 conntrack，可写“只允许已建立连接返回流量”这类规则。
  • UDP/ICMP 虽无连接，conntrack 仍按请求-响应关联建立带超时的伪连接。
  • ufw 是配置前端，不是另一套独立内核防火墙。
  • SYNPROXY：防火墙先代理三次握手，确认客户端像真的，再替后端建立连接。

6. VPN

  • SSH Tunnel 偏向端口/应用转发；VPN 偏向整段网络可达。
  • TUN 处理 IP 包，TAP 处理以太网帧。
  • VPN 程序从 TUN 读到内层包，封装/加密后通过普通 socket 发外层包。
  • 客户端要把“目标私网”路由到 TUN。
  • 必须给“VPN 服务器公网 IP”保留一条经真实网卡的主机路由，避免隧道递归。
  • 服务器要开 IP forwarding，才能在隧道和后端网络之间转发。
  • 隧道短暂中断后 TCP 会不会断，取决于中断时长、重传与超时。
  • 非 host 模式 Docker 抓不到其他容器之间流量，因为它们不在同一网络命名空间视角。
  • select() 用来同时监听 TUN fd 和网络 socket fd。
  • IFF_NO_PI 关闭 4 字节包信息头；配置错会把额外头部误当 IP 头解析，打印出怪异结果。

7. DNS

  • DNS 默认 UDP 53，也可 TCP 53；dig +tcp 可验证。
  • 递归解析路径：根 -> TLD -> 权威。
  • 根服务器地址来源：root hints。
  • Cache Poisoning 根因：DNS 早期无认证、UDP 可伪造、随机性不足、解析器会缓存委派信息。
  • 抢答时关键熵值：事务 ID、源端口；查询名本身也常被随机化利用。
  • Kaminsky：不停问随机子域，制造大量新查询机会，重点毒化目标域 NS 和 glue A。
  • 一旦域的 NS 被毒化，该域下任意主机名都可被攻击者回答。
  • 缓存策略受 bailiwick/授权范围限制，不是附加区所有数据都该缓存。
  • 开放递归解析器可被用于 DNS 放大：小请求打给解析器，大响应反射给受害者。
  • 防御：关闭开放递归、限制客户端、RRL、Anycast、多权威节点、减少超大响应面。
  • DNS Rebinding：浏览器同源策略按主机名，不按解析后 IP；同一主机名先解析到攻击者，再解析到内网设备，JS 就能打内网。
  • 若浏览器长时间缓存该主机名到旧 IP，重绑定成功率会下降。
  • 反向 DNS 结果不能当认证依据，PTR 可被操纵。

8. PKI / HTTPS

  • 证书重点看：Issuer、Subject、公钥、有效期、签名算法。
  • CA 用私钥签发证书，验证方用 CA 公钥验签。
  • “不是受信 CA”=证书链无法回到本地信任库中的根 CA。
  • 站点改主机名后通常要换新证书，因为主机名校验会失败。
  • 直接访问 https://IP 常失败，因为证书通常签给域名，不签给 IP。
  • CA 私钥泄露可导致大规模伪造证书。
  • 若攻击者的自签证书被加入受信列表，相当于植入新的根 CA。
  • Pinning：把服务绑定到预期证书/公钥，降低假证书风险。
  • HTTPS 代理能看明文，是因为客户端主动信任了代理根证书，不是 HTTPS 本身失效。
  • 不要用反向 DNS 得到的名字去验证证书身份。
  • 不要用 strstr() 做主机名校验，evil-vpnserver.com.attacker.com 一类名字会绕过。

9. BGP

  • BGP 在 AS 间传播前缀可达性与路径属性。
  • 一个路由器可能学到多条路径，但通常只把选出的最佳路径通告给某邻居。
  • 不对某邻居转发路由，常因商业/出口策略、社区属性、no-export、避免给对方做 transit。
  • UPDATE 主要看三块：Withdrawn Routes、Path Attributes、NLRI。
  • AS_PATH 用于环路避免和策略判断；最前面的 AS 通常是当前通告者所属 AS。
  • NEXT_HOP 指示实际下一跳。
  • 备份链路控制：
  • 出站偏好常用 local-pref/weight。
  • 入站偏好常用 AS_PATH prepend、MED、运营商社区。
  • eBGP TTL 常设 1，因为对端应是直连邻居。
  • TTL 设 255 常用于 GTSM/TTL Security，防远端伪造会话。
  • BGP 劫持常利用“更具体前缀优先”；防守也常靠通告更具体前缀并联系上游过滤。
  • Anycast 适合 DNS 这类无状态服务；不适合 Telnet 这类强状态会话。

10. 最后必背

  • 访问外网前 ARP 的是网关，不是远端主机。
  • TCP 无消息边界，UDP 有。
  • NF_ACCEPT 不等于“一票通过”。
  • VPN 外层流量不能被再次路由进 TUN。
  • DNS 投毒最值钱的是毒化 NS 委派，不只是改单个 A 记录。
  • DNS Rebinding 绕过的是浏览器按主机名定义的同源策略。
  • 反向 DNS 和字符串包含匹配都不能拿来做安全认证。
  • SSH 能被 RST 断，但难被会话注入。
  • 更具体前缀优先，是 BGP 劫持与防守的共同基础。
